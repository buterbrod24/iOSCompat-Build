# Metadata request and layout-prefix research

Direct source inspection of [Swift 5.7 MetadataValues.h](https://github.com/swiftlang/swift/blob/swift-5.7-RELEASE/include/swift/ABI/MetadataValues.h), [Swift 5.9 MetadataValues.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/MetadataValues.h), and both versions of Metadata.h confirms the four reverse-ordered state values, 8-bit state and nonblocking bit 8. MetadataResponse and MetadataDependency declarations have matching pointer/state fields. A returned response state must be used instead of inspecting concurrently initialized metadata. `metadata_request_model.py` is an independent diagnostic model of known values, not a native ABI implementation or a scheduler. Unknown bits rejected as local policy. Seven synthetic tests include all 16 state comparisons and all eight state/flag round trips.

A separate structural change was found: Swift 5.7 TargetTypeMetadataHeader has a value-witness pointer; Swift 5.9 [Metadata.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/Metadata.h) adds TargetTypeMetadataLayoutPrefix alongside TargetTypeMetadataHeaderBase. The layout-string flag is kind-specific bit 4 in Swift 5.9 MetadataValues.h. [GenMeta.cpp](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/lib/IRGen/GenMeta.cpp) gates layout string emission on a language feature and IRGen option. This does not imply that every modern binary emits layout strings, or that older runtimes necessarily fail. Descriptor inventory now counts the declared bit only, with one synthetic test; no metadata header pointers, layouts, witnesses, private functions, or system files are accessed. Original app audit does not establish whether the flag occurs in its descriptors. The Metadata Probe host results are 12/12 in both modes; actual device report pending. All five missing runtime symbols remain unresolved.
