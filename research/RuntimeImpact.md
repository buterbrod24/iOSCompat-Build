# Swift runtime import impact and symbolic names

The selected-export audit is not a complete loader report. `audit_impact.py` uses the existing validated audit reader, exact libswiftCore provider and the five known runtime entry names to report unique consumers, symbol/consumer pairs and overlap, without consumer paths. Aggregate strength is not assigned to individual binaries. Local independent re-count of the report matched its declared totals. The report itself and its consumer names are not committed.

Swift 5.9 pinned source documentation https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/docs/ABI/Mangling.rst explains that relative markers 0x01–0x17 consume four bytes, absolute 64-bit markers 0x18–0x1f consume eight, and embedded zero bytes do not terminate a symbolic name. 0xff padding may occur. The documentation restricts interpretation of references in uncontrolled inputs. `swift_typeref_inventory.py` therefore only frames bytes in an explicitly named file-backed section of a thin ARM64 Mach-O; it never calculates target addresses, interprets payloads, dereferences, invokes a function, or demangles symbolic references. Counts do not prove that records are valid, complete, or uniquely referenced. Non-observation is not absence. It cannot determine runtime metadata contracts or pointer-authentication compatibility. Six synthetic tests and a compiler-produced original fixture are scheduled. This is diagnostic work, not runtime replacement.
