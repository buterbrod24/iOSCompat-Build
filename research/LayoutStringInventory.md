# Layout-string import and metadata inventory

Inspected Swift 5.9 pinned [Metadata.cpp](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/stdlib/public/runtime/Metadata.cpp) and compared [RuntimeFunctions.def](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/Runtime/RuntimeFunctions.def) with Swift 5.7. Four explicitly named LayoutString runtime declarations appear in 5.9 but not 5.7; the source alone does not establish OS exports or availability. Layout strings describe reference-counting operations; no interpreter or private calls implemented. Local selected-export audit contains none of the four names, but is incomplete and does not establish absence. Original witness fixture CI 46056485344 passed 12/12 host checks in both modes and generated iOS16.2/17.0 evidence. Downloaded evidence archive showed three nominal descriptors per fixture, zero layout-string flag headers and no direct imports of the four names. Those fixtures do not demonstrate layout-string usage. The optional `python3 scripts/analyze_ipa.py input.ipa --metadata --output report.json` integrates existing bounded section readers, separately records errors, aggregates exact provider-qualified layout import observations and does not require extracting or modifying the input. Fat and nonordinary ARM64 slices remain uninspected, descriptor extent validation incomplete. Added two synthetic checks and an original two-image packaging fixture. No private audit or third-party files committed. No assertion of runtime compatibility.
