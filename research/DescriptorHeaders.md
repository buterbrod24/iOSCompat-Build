# Swift nominal descriptor headers

Pinned Swift 5.9 sources, inspected directly: [Metadata.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/Metadata.h) TargetTypeMetadataRecord, TargetContextDescriptor and TargetTypeContextDescriptor; [MetadataValues.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/MetadataValues.h) TypeReferenceKind and ContextDescriptorFlags; [RelativePointer.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/Basic/RelativePointer.h) RelativeDirectPointerIntPair. Record low two bits carry reference kind; remaining signed offset is relative to record. Only direct kind zero is considered, limited to read-only file-backed __TEXT with bounded common nominal prefix. Flags: kind bits 0–4, unique bit 6, generic bit 7, version bits 8–15. Unknown kinds and versions are not interpreted. Counts are header observations, not proof of valid descriptors. Indirect records, parent links, access functions, field layouts, witnesses and generic trailing data are not followed. No loaded-process pointers, authentication changes or execution. No third-party data committed. Runtime entrypoint compatibility remains unproven.
