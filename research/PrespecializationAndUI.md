# Prespecialization and compatibility research

Swift 5.9 release source https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/stdlib/public/core/Prespecialize.swift declares exported array prespecializations with @_specializeExtension, SwiftStdlib 5.9 availability and @_noMetadata Element : _Class. The corresponding Swift 5.7 file https://github.com/swiftlang/swift/blob/swift-5.7-RELEASE/stdlib/public/core/Prespecialize.swift has the metadata warm-up list but not these class-specific extension declarations. The placeholder Builtin.unreachable bodies are compiler directives, not implementations to copy. The specialized entry's metadata-free class constraint differs from an ordinary generic entry's contract; a syntactic name lookup in Array Probe does not certify interchangeability.

Swift ABI mangling https://github.com/swiftlang/swift/blob/main/docs/ABI/Mangling.rst identifies Ts as generic prespecialization. SE-0376 https://github.com/swiftlang/swift-evolution/blob/main/proposals/0376-function-back-deployment.md describes compiler-emitted fallback code for source builds; it does not retrofit an existing binary. Library evolution https://github.com/swiftlang/swift/blob/main/docs/LibraryEvolution.rst requires preserving invariants beyond signature matches. Next array decision depends on physical-device lookup report; no private generic forwarding, runtime replacement, or alias is approved by this audit.

Perception https://github.com/pointfreeco/swift-perception demonstrates source-level Observation integration on legacy SwiftUI with explicit tracking scopes. Apple https://developer.apple.com/documentation/SwiftUI/Migrating-from-the-observable-object-protocol-to-the-observable-macro documents native SwiftUI Observation starting with iOS 17. This motivates an original, limited Combine bridge in observation-ui, not binary compatibility with existing SwiftUI clients.
