# Scroll target research

ShapeStyle CI 46051140392 succeeded. Review of the local app audit found the scroll target family among strong imports, whereas no Bindable names occurred in that report. Absence in a selected-export audit is not proof that the app never uses Bindable. Prioritize observed scroll imports. Apple Beyond scroll views https://developer.apple.com/videos/play/wwdc2023/10159/ and ScrollTargetBehavior https://developer.apple.com/documentation/swiftui/scrolltargetbehavior describe geometry-based snapping and target layouts. UIKit delegate https://developer.apple.com/documentation/uikit/uiscrollviewdelegate/scrollviewwillenddragging(_:withvelocity:targetcontentoffset:) permits an owner to modify the proposed offset. Independent policy selects nearest explicit leading offset, with directional ties and optional integer index limit. This is not Apple's automatic limiting policy, target layout, scrollPosition binding, anchor placement, RTL or lazy geometry discovery. Duplicate IDs rejected; clamped offsets can coincide, so target ID is not a guarantee of visual distinction. UIKit adapter compiles against legacy API, only for an explicitly owned scroll view whose owner supplies coordinates and retains delegate. No delegate replacement or system hooks. Fourteen pure-policy tests and modern SDK client import evidence; actual scroll gesture/deceleration and delegate behavior not yet tested. No native binary replacement.
