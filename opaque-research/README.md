# Opaque type metadata and conformance research

Direct source comparison: [Swift 5.7 Metadata.h](https://github.com/swiftlang/swift/blob/swift-5.7-RELEASE/include/swift/ABI/Metadata.h) and [Swift 5.9 Metadata.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/Metadata.h), TargetOpaqueTypeDescriptor. Common context prefix, generic trailing objects, underlying type argument count in kind-specific flags and relative mangled-name records are present in both. Generic context layout has evolved separately. [MetadataLookup.cpp](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/stdlib/public/runtime/MetadataLookup.cpp) shows that the opaque metadata and conformance functions use underlying mangled names and generic substitutions; the new entrypoints authenticate descriptors and differ from the legacy contract. No private calls, aliases or authentication changes.

Original fixture uses public Swift language features: independent opaque declarations, generic specializations, associated types, nested opaque values and Equatable. Ten host controls observe concrete runtime identities and public generic operations, not source-level opaque identity equality across declarations. iOS 16.2 compilation and 16.2/17.0 compiler-emitted descriptor/name pairs are tested separately using the existing structural demangler. No third-party data or binaries. This is diagnostic evidence, not implementation of missing runtime functions or proof of arbitrary app compatibility. Prior witness control run 46053388196 observed one generic control, template size two words.
