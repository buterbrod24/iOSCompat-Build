# Back-deployment name research

Swift ABI Mangling.rst (https://github.com/swiftlang/swift/blob/main/docs/ABI/Mangling.rst) defines Twb as back-deployment thunk and TwB as fallback. SE-0376 (https://github.com/swiftlang/swift-evolution/blob/main/proposals/0376-function-back-deployment.md) explains client-emitted availability dispatch. Schema 7 records defined local/external section symbols from nlist, excluding debug and undefined symbols. Exact raw stem matches are annotations only, not a proof of linkage, guarded call paths, platform availability, or correctness. No import is downgraded or marked compatible on marker evidence. Missing markers may reflect stripping or optimization. Compiler matrix reuses the actual stock objects and prints marker evidence; no SDK IR or third-party binary is published.

Measured run 46044953460: iOS 16.2 -Onone has two weak factory imports, both thunk names and both fallback names; -O has the two weak imports and two fallback names but no separate thunk names. iOS 17.0 has two strong imports and neither marker at both optimization levels. Analyzer CI passed 21 tests. Schema 8 additionally reads LC_BUILD_VERSION and legacy LC_VERSION_MIN commands using Apple loader.h and LLVM MachO platform definitions. Deployment minimum, SDK and platform are separate declarations, not proof of actual compatibility; no header rewriting or execution-path claims.
