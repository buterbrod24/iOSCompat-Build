# Native metadata identity and completion-related controls

Direct source comparison of [Swift 5.7 Metadata.h](https://github.com/swiftlang/swift/blob/swift-5.7-RELEASE/include/swift/ABI/Metadata.h) and [Swift 5.9 Metadata.h](https://github.com/swiftlang/swift/blob/ea95594ae137f288bf29a0b489b8689680a0086a/include/swift/ABI/Metadata.h) found matching declarations for MetadataInstantiator, MetadataCompleter, MetadataCompletionContext, TargetGenericMetadataPattern and TargetGenericMetadataPartialPattern. The instantiator produces identifying structure; completion may wait for dependencies, and the same completion function for a type must not run concurrently. These source contracts do not prove that implementations or ABI are equivalent.

Original app and host controls exercise public Swift API only: 512 concurrent type identity requests, four specialization groups, nested and recursive generic values, and conditional conformance positive/negative checks. Twelve checks compiled on host with -Onone and -O; ARM64 device IPA targets 16.2 and checks the five unresolved runtime imports are not directly present. The results are indirect observations, not proof of cache internals, cold instantiation, completion state transitions, or absence of dependencies' imports. The diagnostic app writes a START journal and shares the final TXT report. Run on iOS 16.2 only, no system changes, no private runtime calls. Physical device results pending. Prior opaque CI 46054009935: ten host controls passed, five descriptor-owner pairs per target confirmed. No claim of third-party binary compatibility.
